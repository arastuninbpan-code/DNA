# D.N.A. — полный контекст проекта для переноса в ChatGPT

> Загрузите этот файл в новый проект ChatGPT целиком. Перед любой работой нужно также проверить актуальную ветку `main`: https://github.com/arastuninbpan-code/DNA

## 1. Что это за проект

D.N.A. расшифровывается как **Day & Night Assistant**. Это персональное веб-приложение D.N.A. Corporation в фирменном чёрно-золотом стиле.

Репозиторий:
https://github.com/arastuninbpan-code/DNA

Текущий адрес Netlify:
https://soft-cuchufli-21df94.netlify.app/

Netlify-проект: `soft-cuchufli-21df94`.

Основная production-ветка: `main`.

Проект задуман как единый личный помощник с пятью основными разделами:

- Finance — личные финансы;
- Planner — планирование;
- Home — главный экран и будущий голосовой AI;
- Habits — привычки и дисциплина;
- News — персональная новостная лента.

Сейчас полноценно реализованы Finance и Habits. Home работает как главный экран и настройки. Planner, News и голосовой помощник показывают заглушки «в разработке».

## 3. Архитектура

Это полностью статическое приложение без собственного backend.

В репозитории всего три основных файла:

- `index.html` — всё приложение: HTML, CSS, JavaScript, SVG и встроенные изображения;
- `netlify.toml` — публикация корня репозитория без build-команды;
- `README.md` — описание и правила работы.

Отдельные npm-зависимости, сборщик и сервер отсутствуют. Практически весь проект находится в одном `index.html` размером около 923 КБ и 2263 строк. Большая часть объёма связана со встроенными base64-ресурсами.

Плюсы текущего подхода:

- очень простой деплой;
- нет установки зависимостей;
- приложение может работать как один автономный документ;
- исходные данные пользователя не передаются на собственный сервер.

Минусы:

- один большой файл сложно поддерживать и тестировать;
- любое изменение публикует весь файл;
- отсутствуют автоматические тесты;
- отсутствует нормальная система миграций локальных данных;
- embedded base64 увеличивает HTML и время его загрузки/разбора;
- нет облачной синхронизации и резервного копирования.

Не переписывать приложение целиком без отдельного решения владельца. Безопаснее сначала разделить код небольшими шагами, сохраняя внешний вид и данные пользователей.

## 4. Данные пользователя

Все основные пользовательские данные хранятся в `localStorage` конкретного браузера и конкретного домена.

Ключи:

- `transactions` — финансовые операции;
- `goals` — финансовые цели;
- `assets` — активы и инвестиции;
- `dna_finance_opening_v1` — начальный остаток;
- `dna_finance_layout_v1` — порядок и скрытые блоки Finance;
- `dna_habits_v2` — привычки по датам;
- `tinkoff_token` — токен Т‑Инвестиций.

Критически важно:

- очистка данных сайта/браузера удаляет финансы и привычки;
- данные не синхронизируются между компьютером и телефоном;
- localhost и Netlify используют разные хранилища;
- переезд на другой домен не переносит данные автоматически;
- сейчас нет кнопок полноценного экспорта/импорта резервной копии всего приложения.

Перед изменением схемы данных нужно делать обратную совместимость или миграцию старых ключей. Нельзя просто переименовать ключ и потерять существующие записи.

## 5. Навигация и Home

При запуске открывается центральный раздел Home.

Home содержит:

- фирменную заставку DNA;
- центральную кнопку будущего голосового помощника;
- настройки;
- информацию о версии;
- предупреждение, что данные находятся только на устройстве.

Голосовой помощник пока не записывает звук и ничего не отправляет. Нажатие открывает информаальное окно «Скоро».

В настройках указано:

- режим локальный;
- аккаунт и синхронизация будут позже;
- очистка данных сайта может уничтожить записи.

## 6. Finance

Finance реализован как локальный менеджер личных финансов.

Основные функции:

- начальный остаток;
- доходы и расходы;
- категории операций;
- история и фильтрация;
- поиск;
- аналитика по периодам;
- круговая диаграмма расходов;
- динамика доходов/расходов;
- финансовые цели;
- активы и инвестиции;
- ручная настройка порядка и видимости блоков;
- добавление, редактирование и удаление операций;
- экспериментальный импорт текстовых PDF-выписок Т‑Банка;
- обнаружение возможных дублей перед импортом.

Распознавание фото и универсальный PDF-импорт пока не реализованы. Интерфейс честно сообщает об этом.

PDF.js версии `3.11.174` подгружается во время работы с публичного CDN `cdnjs.cloudflare.com`. Это внешняя зависимость, хотя package manager отсутствует.

### Т‑Инвестиции

В интерфейсе существует ввод токена Т‑Инвестиций. Токен сохраняется в `localStorage` как обычный текст под ключом `tinkoff_token`.

В коде существует прямой браузерный запрос к публичному API Т‑Инвестиций с заголовком `Authorization: Bearer ...`. При этом в startup есть комментарий, что broker requests приостановлены до безопасной интеграции, но форма сохранения токена всё ещё может вызвать функцию загрузки портфеля.

Это требует отдельной проверки и приведения к одному состоянию. Не обещать пользователю безопасную интеграцию, пока не решены:

- хранение токена в браузере;
- CORS и корректный метод API;
- минимальные разрешения токена;
- защита от XSS;
- отзыв/удаление токена;
- понятное сообщение об ошибке.

До полноценной безопасной интеграции лучше считать подключение Т‑Инвестиций экспериментальным и не вводить production-токен.

## 10. Запуск локально

Сборка не требуется.

Из корня репозитория:

```bash
python3 -m http.server 8000
```

Открыть:

http://localhost:8000

Важно: локальная версия не увидит данные, сохранённые на Netlify, потому что `localStorage` разделён по origin.

Открывать `index.html` напрямую через `file://` нежелательно: некоторые браузерные функции и импорты ведут себя иначе. Использовать HTTP-сервер.

## 12. Безопасность и приватность

Положительные стороны:

- собственный backend отсутствует;
- финансовые записи и привычки по умолчанию остаются в браузере;
- в GitHub не обнаружено реальных токенов или приватных ключей;
- голосовой помощник пока не записывает звук;
- фото-распознавание пока не отправляет изображения;
- код экранирует пользовательские строки перед вставкой во многие HTML-шаблоны.

Риски и ограничения:

1. Финансовые данные не зашифрованы в `localStorage`.
2. Токен Т‑Инвестиций хранится там же в открытом виде.
3. Любая XSS-уязвимость на домене сможет прочитать эти данные.
4. В `netlify.toml` не заданы CSP, `X-Frame-Options`, `nosniff`, Referrer Policy и Permissions Policy.
5. PDF.js загружается с внешнего CDN без локальной фиксации файла и без Subresource Integrity.
6. Нет резервной копии и восстановления всех локальных данных.
7. Нет автоматических тестов.
8. Нет авторизации: любой, кто откроет браузерный профиль, получает доступ к локальным данным.
9. Нет шифрования или блокировки приложения PIN/биометрией.

Перед подключением облака или реальных финансовых API необходим отдельный security design. Нельзя просто добавить сервер и отправлять туда весь `localStorage`.

## 13. Производительность

Главный документ весит примерно 923 КБ. Это допустимо, но не оптимально для мобильного приложения:

- браузер загружает и разбирает весь HTML/CSS/JS сразу;
- base64-изображения нельзя независимо кешировать;
- любое изменение инвалидирует весь документ;
- PDF.js дополнительно загружается только при импорте, что правильно для первой загрузки.

Безопасные направления оптимизации:

1. вынести изображения в отдельные оптимизированные WebP/PNG;
2. вынести CSS и JS в отдельные файлы;
3. оставить lazy-loading PDF.js;
4. добавить versioned assets и долгий cache для картинок;
5. только после стабилизации рассматривать Vite/PWA-сборку;
6. сохранить совместимость ключей `localStorage`.

Не начинать оптимизацию с полного переписывания: высок риск визуальных и функциональных регрессий.

## 15. Правила дальнейшей работы для ChatGPT

1. Всегда сначала читать актуальный `main`, а не полагаться только на этот файл.
2. Общаться с владельцем проекта по-русски и объяснять результат простыми словами.
3. Не переписывать приложение полностью без явной просьбы.
4. Сохранять чёрно-золотой стиль и текущую композицию.
5. Перед заметным редизайном кратко описать цель и ожидаемый результат.
6. Работать небольшими законченными итерациями.
7. Не удалять и не переименовывать существующие localStorage-ключи без миграции.
8. Никогда не добавлять реальные финансовые токены в GitHub, файлы или сообщения.
9. Отдельно предупреждать о риске потери локальных данных.
10. Проверять touch и desktop после изменений Habits.
11. Обновлять `APP_VERSION` и текст релиза при пользовательском изменении.
12. Делать commit и push только после проверки.
13. После push проверять реальный Netlify, а не только GitHub.
14. Не создавать новый Netlify-site вместо существующего `soft-cuchufli-21df94`.
15. Если Netlify отстаёт от main, сначала диагностировать deploy integration.
